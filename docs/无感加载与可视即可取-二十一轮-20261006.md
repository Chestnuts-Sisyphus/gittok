## 一、N6 可视即可取（P0）

**机制**：`FeedVirtualList` 里预取清单＝虚拟化渲染窗口并集（`visibleIdx`），无任何观察器 API
（open-regression 锁兼容）；`requestIdleCallback`（fallback `setTimeout` 120ms）调度
`feed-payload.prefetchRepoDetails(repos)`——跳过内存/在飞已有者、限并发 6、结果落同一会话内存。
点击可视卡时 `getRepoDetailIfReady` 同步命中 ⇒ `handleOpenDetail` 内存命中分支首帧即 `ready`。

**语义保全（防负优化对照）**：
- boot 关键路径零详情请求：预取只发生在组件 effect 的 idle 回调里（detail 闸 P1 钉「预取自发且晚于首卡」）；
- 弹层 <100ms 不回退（P2/P3/P5/P6/P7/P8 全部带 <100ms 口径）；
- 同日 IndexedDB 分片缓存语义不变（预取命中 IDB 缓存时零网络）；
- boot 载荷增量 +3.5KB（raw）/ +1.4KB（gzip），预算 ≤60KB（读数见 §五）；
- 占位只兜底：竞态路径（点击早于预取到货）仍走「占位→整体交接恰一次」，判据 P3/P4 继续锁。

**闸重写（九判据，CI presentation job）**：P0 分片完整性（不变）｜P1 boot 零关键路径预热
（重写：预取自发⊆可视集）｜P2 **点击可视卡首帧即完整（新 P0 判据）**｜P3 兜底占位先行｜
P4 整体交接至多一次带过渡｜P5 缓存零交接｜P6 缺键显式暂无（搜索路径）｜
P7 分片全 500 韧性（滚屏引入未预取卡）｜P8 收藏路径回归＋全程零未捕获异常（N5）。

## 二、N3 宽度跳变：归因与零 reflow 修复

**归因（修复前探针，线上站，headless 冷 profile ×2）**：宽度时间线全程仅一跳——
探测串 `var(--font-serif)` 306→300px @2741ms，与 `document.fonts` `loadingdone`（Lora 400/500/700）
@2840ms 同窗；二冷样本同跳变（306→300 @3426ms）＝可复现。滚动条假说已在 09-23 G2① 由
`scrollbar-gutter: stable` 修掉，排除。**结论＝Lora woff2（max-age=600）隔 10min 重下 →
`font-display: swap` 换装 → 拉丁/数字 advance width 重排**。

**关键事实（family 链探针）**：本机 swap 前的 latin 渲染者＝**Noto Serif SC**（`--font-serif`
栈内排在 TNR 之前且已安装；去 Lora 栈宽度 306.203 与 NSC 单独渲染精确相等），不是 TNR。
度量比（100px 三串均值，Lora/源）：NSC 族 96.25/95.73/95.24/94.26%（400/500/600/700），
TNR 族 110.93/111.80/107.57/108.40%。

**修复（`web/index.html` ＋ styles.css 栈）**：
- 两个 latin-only 度量对齐兜底面族：`Lora FB NSC`（src local NSC）与 `Lora FB TNR`
  （600/700 用 `local("Times New Roman Bold")`），逐权重 `size-adjust`；
- `unicode-range` 限定 latin：**中文渲染路径一根手指都不动**（CJK 永远 NSC/宋体栈）；
- 栈序＝每个兜底面紧贴其 local 源家族之前：`"Lora", "Lora FB NSC", "Noto Serif SC",
  "Lora FB TNR", "Times New Roman", …`——源家族缺装的机器 local() 失败自动跳过对应兜底面；
- 行高全站显式（styles.css 零 `normal`）⇒ 纵向度量不参与行盒，无需 ascent/descent 覆写；
- 主字重 preload（`lora-latin-400-normal.woff2`，crossorigin）缩短换装窗。

**复验（本地 dist，冷 profile）**：548 帧宽度时间线**零跳变**（修复前 2/2 跳变），
Lora FB NSC 四字面确认注册并参与匹配；真机（有头）1038 帧零跳变。残余风险如实登记：
NSC 若为静态字重安装（本机实测为真权重字面），非 400 档兜底可能有 ≤2% 残差；跨机器
（无 NSC）走 TNR 族，比例独立实测。

## 三、N4 无感加载包

### 1. 网络分解（修复前，线上，本机家宽 headless）

| 资源 | encoded（gzip） | decoded | TTFB | duration |
|---|---|---|---|---|
| index.html | 1,640B | 1,940B | 967ms | — |
| assets/index-*.js | 82,987B | 250,259B | 818ms | 1,153ms |
| assets/index-*.css | 8,988B | 46,527B | 732ms | 742ms |
| **data/feed.json** | **1,377,381B** | 4,902,766B | 1,153ms | 3,163ms |
| Lora woff2 ×4 | ~86KB | ~86KB | 478–868ms | 442–1,024ms |

feed.json＝首载字节 **91%**；双源对照（本机实测）：github.io 1,377,381B enc（ttfb 222–610ms），
jsDelivr 仓库原文件 **3,663,109B enc / 14.2MB dec**（ttfb 6,352–788ms 波动大）。
慢网样本（50KB/s/RTT400ms）：load 5,541ms、feed.json 到货 27.7s 级——与「有时候特别慢」同族。

### 2. SW 壳层预缓存（N4②，`swPrecachePlugin` ＋ `main.tsx`）

- 预缓存面＝hash 资产（assets/*.js|css）＋ fonts/*.woff2 ＋ favicon ＋ **index.html**
  （导航走 network-first，缓存壳只作离线回退——不预缓存它，离线 reload 无壳可用）；
- **失效策略＝版本化缓存名**：清单内容 sha256 → `gittok-precache-<hash>`；部署产物一变即换名，
  activate 删除全部旧 `gittok-*` 缓存；sw.js 自身被 HTTP 缓存拖后（≤10min）时，
  cache-first 未命中的新资产走网络并回填（自愈窗）；
- 数据类（data/*、digests/、agent/、feed.xml、manifest.json）**SW 一律放行**——新鲜度归
  应用层同日 IndexedDB 语义（十二轮资产），SW 不做第二套数据真源；
- 注册在 `load` 事件后（不进 boot 关键路径），失败 console.warn 静默降级。

**闸（`scripts/gittok-sw-check.mjs`，CI presentation job 新步骤）四判据全 PASS**：
S1 注册激活＋预缓存落位（9 件）｜S2 二次访问 0 网络等待（**禁 HTTP 缓存**下 reload：
壳层资产 0 服务端命中、页面照常出卡——防 HTTP 缓存冒功）｜S3 失效策略（服务端模拟新部署
字节差触发更新周期→activate 清掉注入的假旧缓存）＋离线可开（缓存壳＋同日数据）｜
S4 数据放行（SW 控制下 data/* 照常到服务端）。

### 3. feed.json 首屏分片重估（N4③）＝**数据否决，不做**

重估结论必须数据说话（任务书硬性）。探针（`data/feed.json`，3411 卡，gzip level 6）：

- **体积账成立**：head-64 raw 75,922B / gzip 28,949B；head-96 gzip 41,573B；head-128 gzip
  54,497B；head-192 gzip 80,781B——全部 ≤100KB 级，能省首载 gzip ~1.28MB。
- **结构账否决**：`applyJitter` 的骨架是**位次衰减分 `(2 − idx/n)`，n＝池规模**——头片池
  (n=K) 与全量池 (n=3411) 对同一张卡算出的分不同（位次 10 实测差 −7.5%）。24 seeds ×
  K∈{48…192} 全组合实测：**top-24 成员变动最差 18–19/24、位次错位 24/24**（hot/daily、
  纯抖动/带配额全一样）⇒ 全量到货热替换那一帧，用户视野内必然重排＝违反「会话内定序不破」
  （09-05 拍板＋十二轮资产）。再叠 `recapped` 前缀配额（AI≤30% 每前缀，可向深处借非 AI 卡），
  头片保证 top-24 稳定所需的 K **没有数据上界**。
- **裁决**：不做。若未来要做，前置条件＝先改会话洗牌语义（骨架与池规模解耦，另行立项拍板），
  不许在现机制上硬上。多源 fallback＋SW＋preload 已覆盖「无法感知」诉求的主要路径。

### 4. 多源 fallback（N4④）

主源（站点域 `./data/feed.json`）TTFB 闸 8s（只掐响应头，慢网正文不限时）→ 滞留/失败切
jsDelivr 仓库镜像 → 镜像命中后 `canonicalizeFallbackFeed` 剥 detailCn 与构建期死字段到
站点规范形再渲染/入同日缓存（否则 14.2MB 原文件污染 IDB「feed」缓存、revalidate 每次判不等
热替换）。全程 console.warn 留归因证据。诚实边界：分片（构建期产物，不进仓库）与壳层无
镜像，可达性由 SW＋Pages 承担。

### 5. 字体 metric fallback＋preload（与 N3 共用件）

见 §二；preload 使 Lora 400 与 CSS/JS 并行开跑，metric 兜底使换装零 reflow。

## 四、N5 ErrorBoundary＋复验协议

- `web/src/ErrorBoundary.tsx`：三处接线（应用根 / 主内容区 / 详情弹层 overlay）。
  **不吞错误**：componentDidCatch `console.error`（error＋stack＋componentStack 全量证据）；
  可恢复 UI＝重试（reset）＋刷新（reload），弹层形态另有「返回列表」（信息流不陪葬）。
  渲染崩溃从此只能落可恢复 UI，**整树卸载紫屏在机制上不可能**；detail 闸 P8 钉
  「全程 Runtime.exceptionThrown = 0」。
- 收藏/搜索路径入闸回归：P6（搜索，不变）＋P8（收藏夹种子→展开→点卡→弹层照开内容在场）。
- **栗子复验协议（紫屏再现时）**：
  1. 部署后先硬刷新一次（Ctrl+F5）；boot 日志第一行 `[gittok] bundle b<时间戳>` 即当前
     bundle 构建号——先核对它是不是最新（旧标签页跑旧 bundle 是主嫌疑）；
  2. 若再现：**不要关标签页**，F12 → Console 截图（ErrorBoundary 会留下
     `[ErrorBoundary:…] 渲染崩溃（已兜底，未吞错误）` 全量证据，页面同时显示可恢复错误
     卡——不会再是纯紫屏）；记下构建号；
  3. 点「重试」或「刷新页面」应能恢复；把截图与构建号交给下一轮会话归因。

## 七、边界与未竟（如实登记）

- 真机归因探针为 headless/有头 Chrome 自动化，非栗子手感的直接读数；四条反馈的最终复验
  以栗子在真实网络环境的使用为准（协议见 §四）。
- Lora FB NSC 兜底在「静态字重安装」的机器上有 ≤2% 的非 400 档残差（本机为真权重字面，
  实测零跳变）；TNR 族 600/700 依赖 `Times New Roman Bold` 本地名。
- feed.json 首屏分片被数据否决（§三.3），其收益场景（冷首访窄带）由 SW/fallback 部分覆盖；
  若要彻底解决需先立项改洗牌语义。
- jsDelivr 镜像本次实测波动大（ttfb 0.8–6.4s），它是「主源死了」的保险而非加速件。
