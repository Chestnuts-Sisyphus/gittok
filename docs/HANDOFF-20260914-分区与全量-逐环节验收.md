### 2.3 补齐过程（三次踩坑 + 三次加固，全部实测）

| 坑 | 现象（实测） | 加固 |
|---|---|---|
| 通道拖死队列 | `custom:modelscope` 191ms 抛 `Cannot read properties of null`；openrouter 间歇 undefined | **通道预筛**：先发极小请求，只留能回的通道 |
| 并行反噬 | 共享队列+归还 → 3 worker 全扑向唯一健康通道 → `全池 1 账号节流 → 熔断 60s`，1,420/2,308 卡白跑 | **lane-affine 分片**：每条通道只吃自己那份批次 |
| `limit` 哨兵 | CI 传 `ZONE_LIMIT=0`（语义「不限」）被当字面 0 → `slice(0,0)` → **待办恒 0，工作流 20 秒空转**（排查 4 轮） | `limit ≤ 0` 一律 = `POSITIVE_INFINITY` |
| 重试吃光预算 | 2h05m 里 888 张、44 批全在无产出重试上打水漂 | **连败熔断**：同一通道连败 4 批即退出 |
| 推送撞车 | 提交时与并发 tier-drip 抢 `data/feed.json` → rebase 冲突 → `abort` 丢工作树 → run 标红、成果全丢 | `merge -X ours` + 成果先备份 `/tmp` + `continue-on-error` |
| 状态语义 | derived 兜底被写进 `state.done` → 下一轮 `--upgrade-derived` 误判「已完成」直接空转 | `state.done` 只记**模型真判**；derived 不入账 |

### 2.7 最险的一环：分区数据**会被管道自己抹掉**（已根治）【已实测】

1. 回填把判定字段写进 `data/feed.json` → 线上 zone 覆盖率 **100%**

3. 缓存里没有 zone/funScore/domainTags → 线上覆盖率 **100% → 0.2%**
   （2477 张只剩 4 张新卡自带 zone）

只含 `repo/aiDims/aiDim/aiScore/summaryCn/reasonCn/detailCn`，**判定字段全不在内**。
叠加「历史卡零重评」铁律（缓存命中卡不会被重新判定）→
**不进 cache 的字段，下一轮重建就没了**。

**三处修复**（`src/feed/index.ts` + `src/feed/types.ts`）：
1. `loadExistingScores` 带回 `zone / zoneSource / funScore / funScoreSource / tags`
2. 分位归一化分支给本轮新评分盖 `zoneSource/funScoreSource = "model"`
3. 卡片构建透传两个来源标
