# 提案 C2：GPU-hover 满帧门空闲基线前置判据（2026-10-05）

> 状态：**提案，未落码**——等栗子批示后才实施（十九-4 约定）。本文只做判据设计，不改 `gittok-visual-check.py`。

## 一、问题

- 对象：`scripts/gittok-visual-check.py` 的三个帧率断言（`FRAME_NAMES`＝软渲染-hover 满帧 / 软渲染-滚动 满帧 / **GPU-hover 满帧**，`test_hover`/`test_scroll`）。
- 判据现状：`掉帧（帧 >25ms）== 0 且 p95 < 22`——**零容忍**，650 帧里混进 1 个环境抖动帧即整条红。
- 病象：晚间活机器单帧噪声使读数在 `0/650 ↔ 1/647` 间翻转（十八轮实录，A/B＋方差定案为活机器噪声非代码）⇒ 间歇假红，且红/绿与代码质量无关，闸的信号被稀释。
- 现有缓解：`VISUAL_STRICT=css` 可把帧率断言降为信息项（CI 无 GPU 环境用）——但那是**常开豁免**，本地真机跑时要么全硬（吃环境假红）要么全软（失去真机帧率信号），没有「这台机器此刻能不能测」的判断。

## 二、提案：空闲基线前置判据（判据式，不放宽阈值）

**核心**：给三个帧率断言加同一个前置门——**先测环境，再测代码**。判定从两态（PASS/FAIL）扩为**三态**：

```
PASS        基线干净 ∧ 被测段干净
INCONCLUSIVE（环境不可采）基线不干净   ← 本机此刻有噪声，本次读数不作数
FAIL        基线干净 ∧ 被测段掉帧      ← 才是代码红
```

### 判据细节

1. **基线测量**：每个帧率断言开测前，用**同一采样器、同一阈值（>25ms）**在本机采 2s 空闲帧（无鼠标事件、无滚动的静止页面）。
2. **判定**：
   - 基线 `over == 0` ⇒ 环境可采，随后被测段照原判据**零容忍**判（`over == 0 ∧ p95 < 22`，一个字不改）；
   - 基线 `over > 0` ⇒ 本机判「环境不可采」，该断言本轮记 INCONCLUSIVE，**读数里保留基线与被测段两组原始帧数据**（可复跑、可三源交叉）。
3. **逐断言独立**：三个断言各自带基线（GPU 与软渲染是两个不同环境，不能共用一次基线）；基线紧贴被测段之前测（环境尖峰是分钟级瞬时的，隔远了失真）。
4. **读数与汇总**：
   - INCONCLUSIVE 在汇总里单列一行「N 项环境不可采」，**不计入 PASS 总数**（〇块第 6 条：无样本 ≠ 通过，不许让不可采 inflate 绿）；
   - detail 里带原判定（沿用 `VISUAL_STRICT=css` 的「降级不灭证据」惯例：`原判定=…`）。
5. **退出码**：新增 exit 3 ＝「存在环境不可采项且无代码红」（与 exit 1＝代码红、exit 0＝全 PASS 区分）；本地调度器（探针/定时件）拿到 3 可自动重跑一次，CI 里 3 与 0 同样放行但汇总可见。
6. **可选加强（二档判据，等批示选一）**：
   - 甲（保守）：基线 over>0 即 INCONCLUSIVE（如上）；
   - 乙（更稳）：基线连测两次（间隔 1s），两次都干净才可采——把「恰好躲过尖峰」的概率再压一档，成本 +2s。

### 为什么这不是放宽阈值

- 被测代码的判据（`over == 0 ∧ p95 < 22`）**一字不动**；变的是「这次读数是否具备采信资格」。
- 闸的红只会更真：能红=基线干净的环境里被测段真掉了帧；环境的锅不再记到代码头上。
- 与十八轮定案一致：那次 A/B＋方差只能**事后**判「是噪声不是代码」，本判据把同类裁决变成**事前**的机制化判定，人不用再下场复盘。

## 三、影响面与失败路径

- 改动面（获批后）：`gittok-visual-check.py` 新增 `measure_baseline(cdp)` 与三态 `report` 分支；调用点 3 处（两处 `test_hover` 环境 + `test_scroll`）。CI 的 `VISUAL_STRICT=css` 分支保持原样（信息项逻辑不变，在其内层再叠基线判定）。
- 失败路径：基线采样本身异常（frames() 空/CDP 超时）⇒ 同样记 INCONCLUSIVE（不 PASS 不 FAIL）；连续 3 轮 INCONCLUSIVE ⇒ 在汇总尾部提示「本机环境持续不可采，建议换时段」（提示性，不阻塞）。
- 风险：无。纯读数侧改动，不触产品代码，不动 CI 硬拦项（六项审美断言与截图）。

## 四、验收（批示后实施时按此对账）

1. 本机安静时段（基线应干净）跑闸 ⇒ 三帧率断言正常判，行为与现状一致（不引入新红灯）。
