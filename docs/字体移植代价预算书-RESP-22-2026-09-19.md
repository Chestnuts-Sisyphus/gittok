## 三、两处必须公开的更正（推翻本册开头依赖的旧口径）

1. **「439 @font-face」是历史数字，不在当前产物里。** 当前站内 `@font-face` 为 0；439 那笔账属于「如果引入 Google CJK 全量 CSS」的假设代价。
2. **`document.fonts.check` 不能用来判断字族是否可用。** 它对未安装字族回 `true`（因为通用族能兜底），本轮表中「本机在场」列若只看 check 会全绿；甄别办法是**看量出来的单字宽是否与现栈一致**——一致即回落。
   ⚠ 由此带出一条新疑点（记入 0919-03 册块一 C 节续号 C-04）：
   **站内现栈在 Windows 上实测单字宽 16.66px，与强制 SimSun 的 18px 不等 → 说明汉字并非由 SimSun 承接**，
   而是被 Chrome 的 CJK 默认字体接走（YaHei/SimHei 量级）。若属实，CSS 里写 `SimSun` 的那一段意图（要衬线宋体感）**并未生效**，
   属「设计意图与实际渲染不一致」，需要单独定性（不影响功能，影响审美一致性）。

## 四、三选项代价表（选型等裁）

| 方案 | 做法 | 体积/性能代价（实测） | 收益 | 风险 |
|---|---|---|---|---|
| **A 不换** | 文案预算按**最窄值 25 字/行**留余量（G-01 闸的 20-35 字口径不动，只把「一行容量」预算文档从 36 改 25） | **0 字节** | 三平台一致地「宁可截断也不咬行」 | 观感上截断变多（半句比例上升） |
| **B 子集化 webfont** | 自建 `@font-face` 只含 3500 常用汉字子集 | Google 全量 CSS 实测 **202 条 @font-face / 220.2KB**；子集 woff2 抽样 **4.6KB / 15.7KB / 26.8KB** 每档；子集化后可压到单文件 **约 1.2~1.5MB（全字库）或 200~400KB（3500 字）**，首屏必须 `font-display:swap` 否则复现 439 旧伤 | 三平台「每行 N 字」完全一致 | 首次访问多一跳到 gstatic（大陆可达性旧账：见 GT-0819-01）；自托管则要处理仓体积 |
| **C 系统栈调序** | 把栈改成 `"Lora","Songti SC","SimSun","Noto Serif SC",serif`（把确定存在的名字提前） | **0 字节** | Windows 落点变成可控的 SimSun（预算 26.8 字/行），mac 落点变 Songti SC | 只是「让落点可预期」，**不消除**跨平台差异；且与 §三-3 的「现在到底命中谁」耦合，要先定性 |

**Qoder 的建议（等裁，不自行落地）**：先 **A**（零成本、可证伪：把 `.summary` 注释与预算文档改成 25 字/行，并把 G-13 那一档的「一行容量 ≥28 字」验收口径按最窄值重述）；
C 作为「顺手把命中字体钉住」的附加项一起裁；B 只有在要做「三平台像素级一致」的品牌化时才值得付那 200~400KB。
