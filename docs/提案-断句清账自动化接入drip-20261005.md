# 提案 C1：断句清账自动化（接入 drip 管道 / 定时件）（2026-10-05）

> 状态：**提案，未落码**——等栗子批示后才实施（十九-4 约定）。本文只做机制设计，不改任何脚本/workflow。

## 一、问题与史实

- 契约：`reasonCn` 必须以句末标点收尾（口径唯一真源＝`src/feed/taxonomy.ts` 的 `endsWithSentenceEnd`；生成闸＝`src/feed/checks.ts` cardChecks **G1-b 硬**「不合格不写回」；提示词侧 `src/feed/prompts.ts` reason_cn 段同要求）。
- 存量清账：`scripts/gittok-reason-fix.ts`（轻通道，只重写 reasonCn）+ `scripts/gittok-reason-end-audit.ts`（只读清点）。
- **回潮史**：清账后新卡不断把计数顶回去——51→59→92 三次回潮；十八轮人工五轮批跑 92→**4/3381**（当前）。drip（Feed Tier Drip，`feed-tier-drip.yml`，cron `0 */2 * * *`，跑 `scripts/gittok-fullbuild.ts` 后 commit feed）每 2 小时一轮，**新卡必回潮** ⇒ 人工清账是打不完的。
- 回潮源候选（**立项先取证再落码**）：
  1. `src/feed/index.ts` `fitReason()` 兜底分支——超 150 字时先找句末标点，找不到就**从句切**（`[，、；：,;:]` 丢尾）或**裸切 150**，两种兜底产出都**不以句末标点收尾**，是确定性的违约制造点；凡写回路径经过它，回潮必然持续。
  2. `reason-fix --apply-cut`（超长卡确定性切）同属确定性切，理论上同样产违约（十八轮人工批跑时是否触发过需查 state）。
  3. 生成路径本身按 G1-b 硬闸不该放违约进库——若取证显示回潮卡来自生成 lane，则说明某条 lane 绕过了 cardChecks，那是要单独上报的管道缺口。
  - 取证动作：对回潮卡核对 `gSource` 与 reasonCn 长度分布（=150 的占比高 ⇒ fitReason 兜底是主源）。

## 二、方案

### 方案 A（推荐主案）：源头止血——drip 写回出口校验

- **接入点**：`gittok-fullbuild.ts` 的 feed 写回出口（drip 与 fullbuild 共用的唯一出口处，不在多个 lane 分散拦截）。对**本次将被写回的每张卡**复用 `cardChecks`（不另写正则，契约只留一份真源）做写前校验；`reasonCn` 违约的卡**不写新值、保留旧值**，并把违约计数与 repo 清单打进该轮 drip 的 commit message / 读数。
- **为什么是出口**：一处拦截覆盖全部 lane（生成/回填/estimate），新增 lane 天然被盖住；对存量不动作（存量归清账通道管）。
- **幂等**：写前校验本身幂等——同一输入恒同一判定；不合格不写 ⇒ 连跑两轮第二轮零写回。
- **失败路径**：**fail-closed**——校验环节异常（脚本崩/读数失败）⇒ 本批写回整体放弃，等下一轮 cron（2h 天然重试窗）；不允许异常时静默放行。连续 3 轮放弃 ⇒ 走现有 Telegram/飞书通知通道告警。
- **成本**：零 token（纯校验）；改动面＝fullbuild-lib 出口一处 + 读数两行。

### 方案 B（推荐辅案）：清账侧自动化——reason-fix 定时轻批

- **形态**：独立 workflow（推荐，不与 drip 主产物耦合）或 `feed-tier-drip.yml` 附加 step：每 4h 跑 `npx tsx scripts/gittok-reason-fix.ts --limit=16 --max-minutes=20`。
- **幂等**：脚本自带——state 落 `data/reason-fix-state.json`、指纹含口径版本（改契约自动作废旧凭证）；已合格卡不写回。
- **失败路径**：lane 失败走既有 `lane-health` 记账（cooldown/健康度）；workflow 步骤失败即红、可手动重跑，**不阻塞** drip 主产物（独立 job）；`--max-minutes` 兜底防挂死。
- **成本**：每轮 ≤16 卡 × ~200 token ≈ 3k token/4h（上限可调）；免费模型额度内。

### 方案 C（可选升级，等 A/B 稳定后再议）

`gittok-reason-end-audit.ts --strict`（有违约 exit 1）挂进 CI 作 hard 闸——把「存量欠账只报告」升成「进 CI 就拦」。**前提**：A 落地后回潮归零才可开，否则 CI 会被 drip 持续打红（且 CI 无 token 通道，修不了只能红）。

## 三、验收（批示后实施时按此对账）

1. 回潮源取证报告落 docs（回潮卡 gSource×长度分布）。
2. A 落码后：本地模拟 drip 写回（含一张故意超 150 字卡）⇒ 违约卡被拦、旧值保留、读数带清单。
3. B 落地后：连跑 3 轮 cron，`reason-end-audit` 计数不升（维持 ≤4），state 断点续跑可复跑。
4. 以上全部达成后，再议方案 C 是否开。
