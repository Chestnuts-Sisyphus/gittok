## 一、规则（一条，可直接复算）

```
列数 n = max{ n : (W − (n−1)·16) / n ≥ 653 }        # W = 内容网格宽；653 = 一行放得下 35 字
卡宽   = n === 1 ? min(W, 793) : (W − (n−1)·16) / n  # 与 feed-layout.ts feedCardWidthFor() 同式
理由行数 = clamp(ceil(150 / floor((卡宽 − 69) / 13.94)), 3, 4)   # 见第三节
轨道留白 = W − 卡宽（单列档 = W − 793，**对称**分在两侧：justify-content: center）
```

- **轨道里不留空**（卡宽 = 轨道宽）——09-24 栗子红框那条继续成立；
- **轨道之外**的余量 = 对称页边距，**不左对齐、不单侧留**（左对齐是栗子 09-24 明确否掉的形态）；
- 三处同真：`web/src/feed-layout.ts`（推导）·`web/src/styles.css`（`--feed-card-max` /
  `--feed-reason-lines`）·`scripts/gittok-responsive-check.mjs`（R1/R4/R5 判据），由 lock 单测钉住。

## 二、为什么中间带一定有留白（三条口径互斥的证明）

设内容网格宽 W。历史三条口径：① 卡宽 ≤ 793（09-25 栗子）；② 单列不许大块空档（09-24 栗子）；
③ 内容契约不得截断（摘要 20–35 字一行、理由 100–150 字；〇块第 7 条「内容契约优先于版式」）。

- 由 ③ 反推卡宽的**允许区间**：摘要一行放 35 字 ⇒ 卡宽 ≥ 653；理由 3 行放 150 字 ⇒ 卡宽 ≥ 766。
  两列档每列卡宽 = (W−16)/2，单列档卡宽 = min(W, 793)。
- **W ∈ (793, 1322)**（＝视口 ≈1065–1594，覆盖 1366/1440/1500/1536 这些常见窗口）时：
  - 走 1 列 ⇒ 卡宽 = 793 ⇒ 余量 W−793 = 0…528px，**必然**成为留白（② 破）；
  - 走 2 列 ⇒ 卡宽 = (W−16)/2 = 389…653 < 653 ⇒ **摘要与理由都被截**（③ 破，实测见表）；
  - 取消上限 ⇒ 卡宽 = W = 794…1321 ⇒ 栗子 09-25 明确否掉的「太长了」（① 破，1600px 那张卡的原话）。
  ⇒ **三条不可同时成立**；本轮取 ①+③（内容优先），放弃 ② 的「中间带零留白」。

## 三、同轮修掉的那个**真**缺陷：理由行数写死 3 行

- 理由显示侧固定 `-webkit-line-clamp: 3`，而 3 行容量 = 3 × floor((卡宽−69)/13.94)
  **只对卡宽 ≥766 成立** ⇒ 1600 档 72/837（8.6%）、1700 档 7/837 的理由**线上真的带省略号**。
- 改法：行数由内容契约反推（同一条 150 字硬闸），下限 3、上限 4（4 行吃掉卡底 27px 余量后
  实测「可见撑破 0/837」；5 行会溢出 288 卡壳）。**卡高不用改**。
- 结果：1600/1700 档理由被截 **0/837**；793 档仍是 3 行（不动宽卡）；手机档保持 3 行（见下）。
- 闸已补 R5（该档行数 = 反推值 且 0 被截），并证明**植入即红**：把行数钉回 3 行 → R5 红。

# 八轮追加（2026-09-25 晚）—— 栗子给定版口径（本规格的最终规则）

## 一、栗子的两条指令（原话）

1. 「**首先不允许出现留白**，我可以接受两列的时候卡片被缩短，但是第一张图片的那个卡片长度就是卡片极限
   长度了，**再长就要变成两列**。」
2. 「第二张图片所示，**完全错位了，所有的排版出现了问题**，一点都不够优雅流畅统一，观感很难受。」

⇒ ① 废弃七轮「中间带留白消不掉」的结论（那是保内容契约的**代价**，不是必须）；② 列数改由**上限**反解；
③ 新增一条硬要求：**档内统一**（同一档里所有卡的行数/高度/标签行必须一致，不许参差）。

## 二、八轮规则（取代第一节）

```
列数 n = 最小 n 使 (W − (n−1)×16) / n ≤ 793        # 超过 793 就加列 ⇒ 轨道铺满、零留白
卡宽   = n === 1 ? min(W, 793) : (W − (n−1)×16) / n
摘要行数 S = 一行放得下 35 字（floor((卡宽−69)/16.66) ≥ 35）? 1 : 2
理由行数 R = clamp(ceil(150 / floor((卡宽−69)/13.94)), 3, 7)
卡高   H = 288 + (S−1)×25 + (R−3)×23.7              # 卡底余量恒 27px（跨档同节奏）
标签槽位 T = clamp(floor((卡宽−69)/88), 2, 8)        # 余量折进 +N；永不换行 ⇒ 无半截 chip
```

**为什么「窄卡」不用截断兜**：七轮的实测已证 3 行只对卡宽 ≥766 成立（1600 档 72/837 被截）。
八轮把「卡变窄」的代价从「截断」改成「**加行 + 加高**」，内容契约因此在全档成立；
新增的代价是**卡高随档变化**（288→408），由 `--feed-card-h` 逐档下发，虚拟列表垫片同值。

## 一、T1：2 行摘要槽位的空白带 → 流式字号（B 案）

**改前实测**（Range 逐行量「槽位盒高 − 上下内距 − 实排行高」）：
1500 档 **796/837 = 95.1%**、1400 档 **688/837 = 82.2%** 的卡只有 1 行字、槽位是 2 行
⇒ accent 条下半截空着（空白 = 25px，恰好一个行高）。1100 档只有 83/837 = 9.9%（该档一行只放 20 字，
多数摘要本来就会折成 2 行）。两案里**按 B 落码**：

```
摘要字号 f = clamp(内容宽 / ceil(35/行数), 0.81rem, 0.98rem)    # 第 1 行就够 ⇒ 1 行；不够 ⇒ 加行
摘要行数 S = 最少行数使 f ≥ 0.81rem（桌面档只会取到 1 或 2；<349 视口的手机才到 3）
卡高   H = 191.91 + S×(1.5×f) + R×23.7                          # 卡底余量恒 27px 在全档成立
```

- **门槛从 653 下移到 551**：0.98rem(16.66px) 时一行放 35 字要 `35×16.66+69 = 653px`；
  字号收到下限 0.81rem(13.77px) 时只要 `35×13.77+69 = 551px`。1400 档卡宽 556 落在门槛之上
  ⇒ 该档从 2 行槽位变 1 行槽位，**空白带归零**。
- **下限为什么 0.81 而不是 0.82**：0.82rem(13.94px) 时 35 字要 487.9px，而 1400 档内容宽实测
  **487.0px** —— 差 0.9px 就掉回 2 行。13.77px 只需 481.9px（余 5px）；它比理由字号(0.82rem)小 1%，
  肉眼不可辨。
- **卡高跟着字号走**（不是一律减 25）：H 的摘要项是 `S×(1.5×f)` ⇒ 1500 档 337→**310**、1400 档 360→**331**；
  **标准字号档与八轮那版逐像素等价**（S=1,R=3 ⇒ 191.91+24.99+71.1 = 288 ✓）。
- **档内统一**（〇块 14）：同档所有卡共享一组 (S, f, R, H, T)，逐档卡高实测只有 1 个值。
- 变量与真源：App 写 `--feed-summary-font`（px）/`--feed-summary-lines`/`--feed-reason-lines`/`--feed-card-h`；
  CSS 只消费（`.summary` 的 min/max-height 用 `em`，字号一变槽位高自己跟着变）。

## 二、T2：手机档（≤768）纳入自适应

八轮把手机档排除在反推之外（「≤768 不许破」），代价是**每张卡都截断**：390 档实测

## 五、遗留 / 待裁（九轮新增）

1. **卡宽 <551 的 2 行档仍有空白带**（1100 档 9.9%、1200 约 22%、1275 约 35%、1343 约 52%，
   桌面单列带 769–830 同）。几何必然：这些档一行只放得下 20–30 字，**35 字上限放不进一行**
   ⇒ 2 行槽位是唯一不截断的形态，而槽位里只有 1 行文字的卡必然空出下半截。三条可选路（都超出本轮授权）：
   ① 字号继续下探到 0.71–0.78rem（摘要字号会**小于**理由字号；且跨档字号反转：卡更窄字更大）；
   ② 条带贴字（strip 背景跟着文字走、槽位仍固定 ⇒ 空带变普通间距；代价是同档里条的**高度**不一致）；
   ③ 维持现状（〇块 14 已授权的局部不优：档内所有卡的行位置一致）。
2. **最窄手机（320 视口）**：内容宽 227 时 2 行放不下 35 字 ⇒ 摘要走 3 行、卡高 ≈535px，
   超过 320×568 的可视带（514px）。闸的 16 档最小到 390 ⇒ **320 属未验证边界**，如实记。
3. **窄高档（≤560，横屏手机）**：理由按 G-11 锁 2 行 ⇒ 截断（实测 844×390 11/11、667×375 10/11）。
